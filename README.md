# PERSONA 90

**Understand yourself. Challenge yourself. Become yourself.**

PERSONA 90 is a 90-day personal development app. It builds confidence, communication, decision-making, emotional intelligence, independent thinking and leadership through daily practice, with feedback generated by AI and progress that is measured honestly.

## What's inside

| Area | What it does |
|---|---|
| **Initial assessment** | 40 behavioural items (30 self-report, 10 situational judgement) across 10 dimensions, with a published, deterministic rubric. It finishes with two open reflections. The AI writes a development profile and a personalised 90-day roadmap from the results. |
| **Daily check-in** | 5–7 adaptive questions generated from your history, covering real situations, confidence, emotions and decisions. Answers are analysed to find recurring patterns. Scale answers feed your self-report scores. |
| **Daily session (30 min)** | Introduction, an original 1,100–1,400-word story, 3 interactive scenarios, a real-world challenge and a reflection. Steps unlock in order. The story must be read to the end, and the server checks the reading time, before scenarios open. The challenge is recorded separately and can be updated later. |
| **Decision Lab** | Realistic dilemmas with real trade-offs. Your **reasoning** is scored on a four-part rubric. The lab also tracks time to first choice, total time and changes of mind, and shows how well your confidence matches your reasoning. |
| **Communication Lab** | Seven exercise types (opinions, disagreement, criticism, starting conversations, speaking confidently, boundaries, pressure). Replies are scored on clarity, assertiveness, empathy and composure, and you get a stronger version written in your own voice. |
| **AI Coach** | A streaming chat that knows your assessment, scores, check-ins and practice results. It can read your journal only if you opt in. It never diagnoses. |
| **Journal** | Private entries (reflection, observation, decision, emotion, lesson) with mood, tags and Postgres full-text search. |
| **Progress** | Score trends, baseline vs current, a per-skill breakdown table with the reason for each change, and a 90-day activity grid. Everything is built from recorded events, with no back-filled data. |
| **Programme** | Three 30-day phases (Foundation, Development, Transformation). Every third day targets your weakest skills. |
| **Settings** | Profile, timezone, coach journal access, full JSON export and account deletion. Deletion cascades to every table. |

## Scoring model

Each of the 10 dimensions is scored 0–100 and recomputed from stored evidence after every activity (`src/lib/domain/scoring.ts`):

- **Self-reported behaviour (45%)**: the baseline (counted as 3 observations) blended with your last 10 relevant check-in ratings.
- **Demonstrated performance (55%)**: the mean of your last 8 rubric scores from scenarios and labs. It reaches full weight after 3 pieces of evidence.
- **Consistency**: completion of sessions, check-ins and challenges, always reported as its own category. It measures follow-through, so it counts towards Self-discipline only (35% weight), and only from day 7.

Weights are shared out among the components that have data. AI evaluations use fixed rubrics: four 0–25 criteria with written anchors. Every score change is appended to `personality_scores` with its source and an explanation. Scores are presented as development indicators, never as clinical measurements.

## Architecture

```
src/
  app/
    (auth)/          login, signup
    (app)/           authenticated pages (dashboard, today, labs, coach, journal, progress, programme, assessment, settings)
    api/             JSON route handlers (all AI calls happen here, server-side only)
  components/        design-system primitives (ui.tsx), nav, score bars
  lib/
    domain/          pure logic: dimensions, assessment + rubric, programme, scoring engine, labs (unit-tested)
    ai/              Claude client (structured outputs, streaming, refusal fallback), prompts, Zod schemas
    server/          user state, personalisation context, score recomputation, achievements, API helpers
    db/              connection pool, per-user query layer (runs as restricted role with RLS)
    auth.ts          Better Auth configuration
db/migrations/       schema + RLS (applied by scripts/migrate.mjs)
```

- **Frontend**: Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS v4, Recharts, lucide icons.
- **Backend**: PostgreSQL (Neon) with Row Level Security on every application table, and **Better Auth** for email and password login (hashed passwords, database sessions, rate limiting). Migrations in `db/migrations` run automatically before every build.
- **AI**: server-side only, with structured JSON outputs validated by Zod. Three switchable providers, chosen with one environment variable (`AI_PROVIDER`):
  - `gemini`: Google Gemini (`GEMINI_API_KEY`, free tier available; default model `gemini-2.5-flash`)
  - `anthropic`: the Claude API directly (`ANTHROPIC_API_KEY`; `claude-opus-5-5` with server-side refusal fallback)
  - `gateway`: Claude through Vercel AI Gateway, with no key needed on Vercel (OIDC; `anthropic/claude-opus-5.5`)

  If `AI_PROVIDER` is unset, the first configured provider in that order is used. `AI_MODEL` overrides the model. The coach streams its replies. The active provider is shown in Settings.

## Security and privacy

- **Row Level Security** on every table: each request runs as the restricted Postgres role `app_user` with the signed-in user's id set for that transaction, and every policy checks `user_id = app_current_user()`. A missing filter in application code still cannot expose another user's rows, and `app_user` has no access to the login tables. Score history is append-only.
- **Server-side secrets**: the Anthropic key is used only in server code (`server-only` imports) and is never shipped to the browser.
- **Validation**: every request body is checked with Zod. Database `CHECK` constraints bound lengths and ranges.
- **Prompt-injection hardening**: user-written text reaches the model wrapped in `<user_data>` tags, with instructions to treat it as data.
- **Rate limits**: per-user hourly limits on AI-heavy endpoints, plus one session per programme day.
- **Journal privacy**: entries are hidden from the AI Coach unless you opt in.
- **Your data**: export everything as JSON (`/api/export`), or delete your account permanently. Deleting the user row cascades to every table.
- **Hardening**: security headers (HSTS, frame denial, nosniff, referrer policy) and `next` redirect sanitisation on login.
- **AI safety**: prompts forbid diagnosis, shaming and manipulation, and route crisis disclosures to professional help.

## Getting started

1. **Install dependencies**
   ```bash
   npm install
   ```
2. **Create a PostgreSQL database.** On Vercel, use Storage → Create Database → Neon, then connect it to the project; `DATABASE_URL` is added automatically. Locally, any Postgres 15+ works.
3. **Configure environment**: copy `.env.example` to `.env.local` and set `DATABASE_URL`, `BETTER_AUTH_SECRET` and an AI provider (`GEMINI_API_KEY` is free from https://aistudio.google.com/apikey).
4. **Run**. `npm run build` applies migrations automatically; for development run `npm run db:migrate` once, then:
   ```bash
   npm run dev
   ```

## Deployment notes

AI routes set `maxDuration` up to 300 s, because session generation writes a long story. On Vercel this needs a plan that allows long function durations.
